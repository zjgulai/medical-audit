# AI 审计门户化 PRD 调整草稿

## 1. 调整结论

当前系统底座已具备知识查询、疑点清单、复核任务、报告签发、整改跟踪、审计日志和索引管理能力。下一步前端不应继续只按“医保自查 OS”仪表盘扩展，而应调整为“AI 审计应用门户”。

参考系统的核心形态是：

- 左侧主导航承载完整审计 AI 应用模块。
- 顶部多标签承载多任务工作区。
- 中央区域以搜索、筛选、卡片列表、表格、生成器为主。
- 历史对话长期保留在侧边栏，作为审计工作上下文入口。
- 智能体、知识库、文档检索、图谱、底稿报告和项目管理共同构成门户，而不是分散的后台页面。

本调整不改变 V1.0 的业务底线：系统仍是面向单院医疗/医保审计的证据链产品，不升级为开放式通用 AI 平台。

## 2. 证据边界

本草稿基于 2026-06-12 对参考系统 `http://140.210.142.9/ai/` 的只读登录观察和当前生产站 `https://audit.lute-tlz-dddd.top/` 的只读页面巡检。

允许使用的结论：

- 参考系统的导航、页面布局、模块名称和视觉组织方式可作为 UI/IA 目标。
- 当前 AuditScope 已有更深的审计证据链和复核闭环，但前端信息架构不符合门户化目标。

禁止使用的结论：

- 不得宣称参考系统的所有能力已经在当前项目完成。
- 不得把“智能体广场”直接等同于复杂多轮智能体编排。
- 不得把“AI 数据分析”直接写成已完成真实数据分析能力。
- 不得把 fixture 验证写成真实医院数据或客户验收证据。

## 3. 产品定位调整

### 3.1 原定位

当前稳定 PRD 将产品定位为：

```text
知识依据查询 -> HIS 数据审计 -> 疑点识别 -> 人工复核 -> 底稿/报告 -> 整改跟踪
```

该主链路继续保留。

### 3.2 新增门户定位

前端产品层新增门户定位：

```text
AI 审计门户 -> 场景智能体 -> 知识/文档检索 -> 数据分析与疑点识别 -> 复核底稿报告 -> 项目与知识治理
```

调整后的产品首屏不再强调“今日工作台”，而是强调“AI 审计应用”的模块入口和审计人员日常工作路径。

## 4. 目标信息架构

| 导航模块 | 目标说明 | 当前映射 | PRD 状态 |
| --- | --- | --- | --- |
| AI 对话 | 审计人员的自然语言入口，支持选择助手、附件、引用依据和生成可追溯回答 | `/pages/chat` | 已有能力，需门户化改版 |
| 我的智能体 | 用户收藏或配置的审计助手列表 | 当前无独立页 | 新增轻量页，先做场景模板，不做复杂 agent 编排 |
| 智能体广场 | 审计智能体/场景模板市场，支持分类、搜索、分页 | 当前无独立页 | 新增展示页，首期基于内置模板 |
| 知识库 | 展示法规库、规则库、个人知识库、系统知识库和关联应用 | `/pages/index-admin`、知识索引状态 | 新增产品化知识库页，运维能力仍在索引管理 |
| 文档检索 | 面向文档和知识库的统一检索页，含搜索历史、库分类、对话文档和知识库文档 | `/knowledge-query` | 需重构为参考系统式检索首页 |
| AI 数据分析 | 对审计数据和上传文件进行分析的入口 | 当前无完整页 | 首期只作为“数据分析入口/占位 + 与疑点任务联动”，不宣称真实 BI |
| 知识图谱 | 展示项目实体、文档、规则、疑点和人员之间关系 | 当前桥接到工作台 | 新增只读图谱列表页；完整图谱交互后置 |
| 审计底稿/报告 | 从历史对话、复核任务和疑点生成底稿/报告 | `/pages/review-tasks` | 需新增首页，保留复核任务深页 |
| 项目管理 | 项目列表、成员数、创建人、项目空间入口 | 当前 hard-coded project context | 新增项目列表页，先读已有项目数据或 fixture |

## 5. 导航与页面布局要求

### 5.1 全局壳

目标壳结构：

- 左侧固定导航，宽度约 `220px`。
- 顶部栏包含折叠菜单、当前页面标题、用户头像/账号。
- 顶部标签栏显示已打开模块，支持关闭标签。
- 内容区白底或浅灰底，模块内容居中并保持业务后台密度。
- 左侧下半区保留历史对话入口。

当前侧边栏描述文案过长，且卡片化仪表盘色彩更接近内部运营台。门户化改版应降低说明文字密度，采用“图标 + 模块名”的导航表达。

### 5.2 视觉原则

- 主色使用审计门户蓝，不继续强化“医保自查 OS”的强场景色。
- 页面内容以搜索、筛选、列表、卡片、表格为主。
- 减少大面积 hero 和过厚卡片阴影。
- 保留当前项目的证据链严谨性，但减少面向用户的工程术语，如 `API-first`、`store`、`backend`、`persistent`。
- 首页和列表页优先服务审计人员扫描，不做营销式介绍。

## 6. 模块级调整要求

### 6.1 AI 对话

目标：

- 作为默认首屏。
- 保留历史对话列表。
- 中央输入框支持问题输入、附件、助手选择。
- 下方展示“我的助手”推荐卡片。

当前能力映射：

- 复用 `/pages/chat` 的引用型回答、来源过滤、底稿导出和创建复核任务能力。

需调整：

- 页面标题从“医保审核对话审证台”调整为“AI 对话”。
- 推荐问题改为审计任务历史和智能体卡片。
- 输出区仍必须显示引用、证据质量和原文预览，不能降级为普通聊天气泡。

### 6.2 我的智能体

首期定义：

- 智能体不是独立模型编排，而是审计场景模板。
- 每个智能体包含名称、分类、审计专题、适用项目、提示词/规则说明、关联知识库、是否已关联项目。

首批内置模板建议：

- 医保重复收费核验
- 城乡居民医保报销政策执行核验
- 医保目录限制条件核验
- 门诊超量开药核验
- 审计底稿生成助手
- 合同/会议纪要要素提取助手

### 6.3 智能体广场

目标：

- 参考系统式两列卡片。
- 分类筛选：全部、效率类、业务类、研究类。
- 专题筛选：医保审计、财政审计、社保审计、国企审计、采购审计等。

当前 V1.0 只允许重点实现医疗/医保审计相关模板。其它专题可展示为路线图或禁用态，不进入交付承诺。

### 6.4 知识库

目标：

- 将当前索引管理中的知识资产产品化展示。
- 区分个人知识库、系统知识库、公开知识库。
- 显示文档数、字符数、关联应用数、创建者、描述。

首期知识库分类：

- 审计常见问题
- 审计定性依据
- 国家法律法规
- 医保目录与政策
- 智能监管规则
- 风险负面清单

运维类索引发布、回滚、active version、embedding 计数仍保留在“索引管理”或管理员入口，不暴露在普通知识库首页。

### 6.5 文档检索

目标：

- 从当前“查询工作台”升级为文档检索首页。
- 支持搜索框、仅标题开关、搜索历史、知识库分类统计、对话文档、知识库文档。

当前能力映射：

- 复用 `/api/v1/query`、引用证据、原文预览、来源过滤。

需调整：

- 搜索结果展示按文档分组，而不是只按 citation 行展示。
- 保留“转入 AI 对话/审证”的入口。
- 明确无引用拒答和证据质量，不隐藏当前系统的审计门禁。

### 6.6 AI 数据分析

首期边界：

- 不直接承诺通用数据分析。
- 先定义为“审计数据分析入口”，承接 HIS staging、规则运行、疑点统计和文件分析。

首期页面内容：

- 数据源卡片：HIS staging、规则运行、疑点清单、复核分布。
- 分析入口：重复收费核验、目录限制核验、超量开药核验。
- 文件分析入口：上传/选择已归档文档后进入文档检索或对话审证。

后置能力：

- 真实表格分析、SQL 生成、图表分析、BI 仪表盘。

### 6.7 知识图谱

首期边界：

- 只做项目图谱列表和静态预览，不做复杂交互图编辑。

节点关系建议：

- 项目
- 知识库
- 文档
- 规则版本
- 审计任务
- 疑点
- 复核任务
- 报告
- 整改事项

### 6.8 审计底稿/报告

目标：

- 新增底稿/报告首页，展示历史生成记录、可选择对话/复核任务、一键生成底稿入口。
- 保留当前 `/pages/review-tasks` 作为复核和签发深页面。

首期内容：

- 历史生成记录列表
- 可勾选历史对话或复核任务
- 报告草稿状态
- 正式报告签发状态
- 整改状态

### 6.9 项目管理

目标：

- 参考系统式项目表格：序号、项目名称、成员数、创建人、创建时间、操作。
- 支持项目搜索和创建入口。

首期边界：

- 先展示单院项目列表和进入项目空间。
- 项目成员、权限和邀请流程可后置。

## 7. 与现有 PRD 的冲突处理

### 7.1 智能体冲突

稳定 PRD 写明 V1.0 不做复杂多轮智能体编排。门户化需求要求出现“我的智能体/智能体广场”。

处理方式：

- 首期把智能体定义为“审计场景模板 + 知识库/规则/提示词绑定”。
- 不实现 agent toolchain、自动规划、多步自主执行。
- 页面文案避免承诺“自主办案”。

### 7.2 AI 数据分析冲突

当前系统已有 HIS fixture 和疑点链路，但没有完整 BI 数据分析。

处理方式：

- 首期只做审计数据分析入口和已存在统计的产品化呈现。
- 真实分析能力进入二期。

### 7.3 项目管理冲突

原 MVP 暂不做重量级项目管理。

处理方式：

- 首期做轻量项目索引和项目上下文。
- 不做组织级多项目权限、复杂成员治理和流程引擎。

## 8. 实施分期

### Phase 1：门户壳与导航重组

目标：

- 完成左侧导航、顶部栏、多标签栏、历史对话区。
- 把现有真实能力映射到新导航。
- 消除“导航按钮没有实际内容”的产品债。

交付页面：

- AI 对话
- 文档检索
- 疑点/AI 数据分析入口
- 审计底稿/报告入口
- 项目管理入口
- 知识库入口
- 智能体列表入口

验收：

- 所有左侧导航都有真实页面，不再只显示 bridge/plan。
- 现有知识查询、疑点、复核、签发、整改能力不回归。
- 页面不出现误导性“已完成智能体编排”表述。

### Phase 2：知识库、文档检索、底稿报告首页产品化

目标：

- 将后台能力转为参考系统式业务首页。
- 普通用户不直接接触索引发布和后端状态。

交付页面：

- 知识库列表
- 文档检索首页
- 审计底稿/报告首页
- 项目管理列表

验收：

- 文档检索能展示搜索历史、库分类、对话文档、知识库文档。
- 底稿/报告首页能展示历史生成记录和复核任务入口。

### Phase 3：智能体与图谱能力深化

目标：

- 智能体从模板展示升级为可配置审计助手。
- 图谱从静态列表升级为可交互关系视图。
- AI 数据分析接入真实 HIS 数据分析和规则运行统计。

前置条件：

- 数据模型确认。
- 用户权限确认。
- 院方审计场景和报告模板确认。

## 9. 需要需求方确认的问题

### 9.1 已确认决策表

| 编号 | 决策问题 | 需求方确认值 | 取舍影响 | 执行口径 |
| --- | --- | --- | --- | --- |
| D1 | 产品名称是否从 `医保自查 OS` 调整为 `AI审计应用` 或 `AuditScope AI审计应用` | 改名为 `AI智能审计管理系统` | 产品定位从单一医保自查工作台上移到审计 AI 管理系统，但 V1.0 业务范围仍保持单院医疗/医保审计 | 前端品牌、PRD 标题和页面主标识使用 `AI智能审计管理系统` |
| D2 | `智能体` 是否允许首期定义为“场景模板”，而不是完整 agent 编排 | 允许；一个智能体对应一个提示词，可新增智能体 | 满足参考系统“提示词类型智能体”形态，不引入多步 agent 编排复杂度 | 实现智能体列表、分类、搜索、新增和提示词配置；不做自动工具编排 |
| D3 | 参考系统中的财政、农业、国企、采购等专题是否只是 UI 参考，还是当前项目也要展示跨行业专题 | 只是 UI 参考 | 避免范围扩张为跨行业通用审计平台 | 当前项目默认只展示医疗/医保审计专题 |
| D4 | `AI 数据分析` 首期是否接受“审计数据分析入口 + 已有疑点统计”，还是必须具备上传表格分析能力 | 必须具备上传表格分析能力，同时接受审计数据分析入口 | 前端改版必须新增文件上传、表格解析、分析结果展示和审计数据入口 | 首期至少支持表格上传分析的可演示闭环，真实生产规则和大文件能力可分级实现 |
| D5 | 项目管理首期是否只需要项目列表，还是必须包含成员管理 | 必须包含成员管理 | 项目管理从只读列表升级为协作管理模块，需要成员列表、角色、添加/移除或禁用态设计 | 首期至少提供项目列表、成员列表、成员角色展示和新增成员入口 |
| D6 | 知识库是否需要区分个人、系统、公开三类 | 区分，首期只读展示 | 满足参考系统知识库分类，不提前承诺完整管理流 | 展示个人知识库、系统知识库、公开知识库；创建/维护可后置 |
| D7 | 顶部多标签是否作为硬性要求 | 作为 UI 硬性要求 | 必须实现参考系统式多任务工作区 | 实现打开、切换、关闭标签；首期可前端状态，不要求服务端持久化 |

### 9.2 推荐会议议程

1. 确认 `AI智能审计管理系统` 的页面品牌表达和英文副标题是否需要保留 `AuditScope`。
2. 确认导航模块完全对齐参考系统 9 个入口。
3. 确认智能体数据字段：名称、分类、提示词、关联知识库、关联项目、创建人、更新时间。
4. 确认上传表格分析的首批文件类型、大小限制和输出结果格式。
5. 确认项目成员管理的角色集合和新增成员是否需要真实写库。
6. 确认知识库三类只读展示的数据来源。
7. 确认 PRD 晋升路径：本草稿确认后再改稳定 PRD 和前端实施计划。

## 10. 下一步

需求方已确认本草稿的 D1-D7 决策，正式 PRD 和实施计划已完成同步。下一步进入前端改版代码实施前，应先基于 `workflow-frontend-ai-audit-portal-refactor-stable.md` 拆分第一批开发 PR：

1. Phase 0：冻结当前视觉与功能基线。
2. Phase 1：实现门户壳、9 模块导航和顶部多标签。
3. Phase 2：实现提示词型智能体列表、广场和新增入口。
4. Phase 3：实现知识库和文档检索首页。
5. Phase 4：实现上传表格 AI 数据分析和项目成员管理。
