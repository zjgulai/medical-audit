# AI 审计门户 Phase 0 现状基线诊断

## 1. 结论

[事实] 当前生产站点并不是“功能都没有开发”，而是“真实能力分散在少数 Next 原生页和后端兼容页，多个新产品入口仍是桥接页”。

[事实] 当前前端主品牌仍是 `AI 医保自查 OS / Medical Audit Self-Check`，后端兼容页仍是 `AuditScope 医保审计证据控制台`，尚未统一为 `AI智能审计管理系统`。

[事实] 当前左侧导航只有 7 个主入口，不满足已确认 PRD 的 9 模块门户要求，也没有顶部多标签工作区。

[推断] 下一步不应重新开发一套空门户，而应把已有真实能力迁移、包装或嵌入到统一门户壳中，并把桥接页升级为真实模块页。

反面论点：桥接页本身不是错误，它曾经用于清理 plan 页和保护已上线能力。但在 `AI智能审计管理系统` 的新 UI 要求下，桥接页已经成为产品集成债务。

## 4. 与目标 PRD 的差距

| 目标要求 | 当前状态 | 债务类型 | Phase 1 处理策略 |
| --- | --- | --- | --- |
| 产品名称统一为 `AI智能审计管理系统` | Next 和后端兼容页仍使用旧品牌 | 产品集成债务 | 先改 Next 门户壳和页面标题，后端兼容页保留兼容标识但降低露出 |
| 左侧 9 模块导航 | 当前只有 7 个主入口 | 信息架构债务 | 重建导航模型，按 PRD 定义 9 模块 |
| 顶部多标签工作区 | 当前无 tabs | 交互框架债务 | 在 `WorkspaceShell` 层新增 tab state 和标签栏 |
| 智能体为提示词类型 | 当前只有对话审证页，无智能体管理 | 产品功能债务 | 新增智能体列表和新增提示词表单，调用对话能力而不做编排 |
| 文档检索首页 | `/documents` 只是桥接 | 产品集成债务 | 包装 `/knowledge-query` 的能力，增加搜索历史、库分类和文档分组 |
| AI 数据分析支持上传表格 | `/analytics` 指向索引管理 | 功能缺口 | 新增 `.xlsx/.csv` 上传 UI 和本地字段概览，审计数据分析入口复用后端能力 |
| 项目管理包含成员管理 | 当前无独立项目管理页 | 功能缺口 | 新增项目列表、成员列表、角色展示和新增成员入口 |
| 知识库区分个人/系统/公开 | 当前以索引管理表达知识库 | 表达债务 | 首期只读展示三类知识库，不开放复杂治理 |

## 5. Phase 1 不变量

Phase 1 改门户壳时必须保持以下能力不回退：

- `/workspace` 仍能显示项目状态、待办疑点、补证任务和索引健康。
- `/knowledge-query` 仍能提交查询并展示引用、原文预览和证据分组。
- `/findings` 仍能展示疑点、源记录定位、计算过程和证据项。
- `/pages/chat` 仍能生成可追溯回答，并保持“无引用不结论”。
- `/pages/review-tasks` 仍能维护复核状态、底稿、附件、报告签发和整改跟踪。
- `/pages/audit-logs` 仍保持权限边界，不向无权限角色泄露事件内容。
- `/pages/index-admin` 仍保留索引发布、回滚、重载和验收能力。

## 6. Phase 1 进入条件

- 以本基线为回归对照，不再新增临时 plan 页。
- 先改导航模型、门户壳、品牌和 tabs，再处理深层业务表单。
- 后端兼容页暂不删除，作为迁移期真实能力兜底。
- 所有新增模块必须有真实内容来源；没有真实能力的模块只能标注为首期只读展示，不能伪装成已闭环功能。

## 7. Phase 1 首批实现切片

1. `PORTAL-01`：品牌、页面标题、侧边栏、顶部栏和 9 模块导航。
2. `PORTAL-02`：顶部多标签工作区，支持打开、切换、关闭。
3. `PORTAL-03`：桥接页升级策略，优先处理 `documents`、`analytics`、`reports`、`archive/project`。
4. `AGENT-01`：提示词型智能体列表、新增智能体表单和对话入口绑定。
5. `DATA-01`：上传表格分析入口，输出字段概览、行列统计和初步线索。
6. `PROJECT-01`：项目管理和成员管理只读/轻写 UI。
