# 重构前端对抗式 UI/UX 审计与精修计划

## 审计边界

本轮审计基于本地生产式预览 `http://localhost:3034`，覆盖 21 条前端路由、桌面与移动两个视口、内部链接探测和关键交互抽样。审计结论不代表生产环境已经更新，也不代表后端、知识库、索引或 provider 能力已经验收。

证据文件：

- 页面截图：`web/output/adversarial-frontend-audit-20260704/*.png`
- 页面指标：`web/output/adversarial-frontend-audit-20260704/metrics.json`
- 交互探针：`web/output/adversarial-frontend-audit-20260704/interaction-probes.json`
- 构建证据：`corepack pnpm --dir web build` 通过，生成 24 个静态页面。

## 第一性原理判断

医保智能审计产品的第一性目标不是“像 AI 产品”，而是让审计人员在高责任场景中快速形成可信判断。界面必须同时满足四个底层要求：

1. 可信：视觉语言应接近政务、监管、审计系统，而不是通用 AI SaaS。
2. 可扫读：首屏必须让用户在 5 秒内知道当前页面能做什么、下一步点哪里、风险在哪里。
3. 可闭环：每个按钮要么跳转、要么改变状态、要么打开明确的弹窗/抽屉，不能只给“本地门禁”类开发提示。
4. 可演示：页面在桌面和移动端都不能出现密度失控、小点击目标、重复命名、加载失败和 500 报错。

当前重构版本已经比前一版更接近参考图，但仍是“局部精修、整体未收敛”的状态。最主要的问题不是单个颜色或卡片，而是信息架构、组件语言、交互闭环和内容语气没有统一。

## 全局高风险问题

### P0：核心页面出现真实失败态

- `/findings` 显示“加载失败”，疑点清单是审计系统核心任务页，不能在演示或验收中以失败态作为默认状态。
- `/knowledge-query` 触发 `/api/v1/query` 返回 500，前端没有先做足够的输入校验和可恢复提示。

修复要求：

- `/findings` 增加稳定静态 fallback 数据和空状态，不允许默认红色错误块占据主视觉。
- `/knowledge-query` 在空查询、后端不可用、超时和 500 四类情况下给出不同 UI；空查询不应发起 API 请求。
- 将 API 错误从“浏览器 console 失败”转为页面内可解释状态：`当前仅展示样例结果 / 后端暂不可用 / 可继续本地检索演示`。

### P1：设计语言分裂

- `/chat` 和 `/documents` 已明显接近参考图。
- `/medical-audit` 仍是高密表格后台系统。
- `/archive`、`/rules`、`/remediation`、`/guided-check` 是旧后台卡片堆叠风格。
- `/login` 虽复刻了大体结构，但缺少官方纹理和更强品牌识别。
- `/` 与 `/workspace` 使用不同壳层，视觉体系不一致。

修复要求：

- 建立一套统一的 `OfficialAuditPage` 页面框架：左侧导航、顶部条、页签、页面 hero、纹理底、主操作区、辅助区。
- 旧 `audit-*` 样式逐步迁移到 `replica-*` 或新的 `official-*` token，不允许两套系统并行扩散。
- 每个页面只保留一个主要行动按钮和 2-3 个次级入口，其余收进更多菜单或详情抽屉。

### P1：文本密度和后台语言过重

高密页面：

- `/archive`：桌面 text density 12.68，移动页面高度约 5903px。
- `/remediation`：桌面 text density 9.03，移动页面高度约 4833px。
- `/rules`：桌面 text density 8.90，移动页面高度约 4485px。
- `/guided-check`：桌面 text density 8.41，移动页面高度约 5486px。
- `/documents`：桌面 text density 8.07，移动页面高度约 4213px。

修复要求：

- 页面首屏只保留：当前任务、关键状态、主操作、2-4 个指标。
- 把 backend/internal 术语换成用户语言：`fallback`、`local gate`、`store.ready`、`manifest`、`production_side_effect` 不直接出现在用户界面。
- 长说明改为短句：标题 5-12 字，描述 18-28 字，状态 2-6 字。
- 技术细节只放“详情”抽屉，不进入首屏。

### P1：可访问性和自动化定位不稳定

交互探针发现多处重复可访问名称：

- `/login`：`getByLabel('密码')` 命中两个元素。
- `/chat`：`智能体广场` 同时出现在侧栏和快捷入口。
- `/documents`：`搜索`、`常见问题库` 出现重复可访问目标。
- 多数页面页签关闭按钮只有 18x18，小于移动端 44x44 推荐目标。

修复要求：

- 所有重复按钮添加上下文 aria-label，例如 `快捷入口：智能体广场`、`主导航：智能体广场`。
- 关闭按钮视觉可小，但 hit area 必须至少 40x40。
- 每个 tab、筛选、卡片操作必须有唯一名称。
- 所有 icon-only 按钮必须有明确 tooltip 和 aria-label。

### P1：交互闭环不够产品化

许多按钮点击后只是局部文字变化或无明显反馈：

- `/analytics` tab 和开始分析反馈不明显。
- `/agents` 查看详情按钮交互后视觉变化不足。
- `/reports` 未选择历史会话时点击生成，交互探针未检测到明显状态变化。
- `/knowledge-base` 筛选变化不明显。

修复要求：

- 所有主操作统一采用：加载态、完成态、错误态、撤销/返回入口。
- 本地演示能力统一显示为“预览结果”而不是“本地门禁”。
- 详情类操作统一打开右侧抽屉，保留当前上下文。

### P1：真实图形资产不足

除了 logo，绝大多数页面没有真实图片或 SVG 资产，主要依赖 CSS 方块、线条和 icon。当前官方质感靠统一底纹补了一层，但还缺少“页面级视觉锚点”。

修复要求：

- 为 5 类页面建立官方插图组件：
  - 审计对话：对话气泡 + 文档引用。
  - 文档检索：档案柜 + 放大镜。
  - 数据分析：表格 + 趋势线。
  - 医保审计：票据/病例/规则链。
  - 归档报告：文件盒 + 签章链。
- 插图不使用花哨渐变，不使用 AI 紫；采用政务蓝、浅灰、白底、细线、低饱和辅助色。
- 每页至少有一个视觉锚点，不再完全由卡片堆叠构成。

## 页面级审计与解决方案

### 1. `/login`

问题：

- 整体结构接近参考，但卡片偏小、留白过空，官方质感弱。
- logo 与参考图的视觉重量不足。
- 密码显示按钮只有 24x24，移动和桌面都偏小。
- 安全提示弹窗没有关闭按钮，用户只能选择流程按钮。
- `密码` label 与新密码弹窗 label 会造成自动化/辅助技术定位歧义。

精修方案：

- 卡片宽度调到 520-560px，logo 区和标题区增加参考图式上下节奏。
- 背景加入极浅的官方线性纹理和中心柔光，不使用 AI 渐变。
- 密码可见按钮 hit area 扩到 44x44，图标改为统一线性 eye icon。
- 安全提示弹窗增加右上关闭，Esc 可关闭。
- label/aria 区分为 `登录密码`、`新密码`、`确认新密码`。

### 2. `/`

问题：

- 主页与 `/workspace` 不是同一套壳层，像旧入口残留。
- 缺少官方背景纹理和页面级插图。
- 用户进入根路径时看到的不是最新重构体验。

精修方案：

- 直接重定向到 `/workspace`，或使用同一 `ReplicaShell`。
- 根路径不再保留旧 `WorkspaceShell`。

### 3. `/workspace`

问题：

- 首屏仍有“知识库暂未连接”等开发/状态语言，影响可信感。
- 工作台缺少明确的“今天该做什么”主流程。
- 视觉上仍偏卡片拼装。

精修方案：

- 首屏改为“今日审计概览”：待处理、待证据、待复核、已完成。
- 将连接状态降级到右上角状态胶囊，不作为主内容。
- 增加审计链路插图：资料进入、规则命中、人工复核、报告输出。
- 增加一条清晰主 CTA：`进入医保审计`。

### 4. `/chat`

问题：

- 当前已经最接近附件，但仍存在几个专业度问题：侧栏历史过密，快捷入口与侧栏重复命名，模型名 `Kimi K2.5` 对业务用户有技术暴露感。
- 输入框下方工具按钮没有完整 tooltip。
- `+` 添加内容只显示本地门禁提示，不像正式产品。

精修方案：

- 模型 chip 改为 `快速模式`，hover/tooltip 才显示模型详情。
- 快捷入口 aria-label 加 `快捷入口：` 前缀。
- 历史对话只展示最近 5 条，更多进入“历史”抽屉。
- `+` 按钮打开附件菜单：上传文件、选择知识库、粘贴文本。

### 5. `/agent-market`

问题：

- 智能体卡片仍偏后台目录，不像精选助手库。
- 部分卡片操作目标偏小，移动端按钮高度约 32px。
- 筛选分类自动化未能命中 `医保基金`，说明可见标签或命名与预期不一致。
- 查看详情只给轻量反馈，没有正式详情页/抽屉。

精修方案：

- 卡片名称压缩到 5-10 字：如 `流程核验`、`政策速查`、`疑点归因`。
- 卡片结构统一为：名称、适用场景一句话、可信来源、主按钮。
- 详情打开右侧抽屉：能力说明、输入示例、输出样例、适用知识库。
- 移动端操作按钮高度至少 40px。

### 6. `/agents`

问题：

- 桌面 39 个按钮，移动 38 个按钮，控制密度最高之一。
- 每张卡同时展示查看、编辑、历史版本、删除，移动端页面极长。
- 点击“查看详情”后探针未检测到明显状态变化，反馈不足。

精修方案：

- 卡片只保留主按钮 `使用` 和更多菜单。
- 编辑、历史、删除收进 `...` 菜单。
- 详情统一右侧抽屉，移动端底部 sheet。
- 增加批量管理模式，默认不展示危险操作。

### 7. `/documents`

问题：

- 视觉方向正确，但页面过长，桌面 text density 8.07，移动高度约 4213px。
- 出现非医保场景内容：劳动争议、招投标、CEO 问题，与当前产品域不一致。
- `搜索`、`常见问题库` 等重复命名造成定位歧义。
- 搜索结果区同时有“对话文档”和下方“检索结果”，信息层级重复。

精修方案：

- 默认查询和历史词换成医保审计语境：`医保目录限制`、`重复收费`、`DRG分组`、`监管两库`。
- 保留顶部文档库和对话文档，下面结果默认折叠到“更多结果”。
- 所有库 tile 增加唯一 aria-label：`选择文档库：常见问题库`。
- 移动端库区改为横向滑动，避免七个 tile 竖向堆叠。

### 8. `/analytics`

问题：

- 页面基本可用，但缺少图形资产和实际图表占位。
- `本地模拟`、`本地门禁` 直接暴露工程状态。
- 文件上传只是记录文件名，缺少上传后表格预览和模板选择。

精修方案：

- 首屏增加数据分析插图和三步流程：上传、识别、生成。
- 替换工程文案为 `预览模式`、`待接入正式分析任务`。
- 上传后展示三类表单模板：费用汇总、费用分类、就诊明细。
- 图表 tab 增加真实空态图表骨架。

### 9. `/archive`

问题：

- 高密度页面，桌面 text density 12.68，移动高度约 5903px。
- 页面把很多归档策略、签名链、保留周期、目录字段平铺展示，像运维配置页。
- “查看档案/查看留痕”重复按钮多，层级不清。

精修方案：

- 首屏只展示归档健康度、待归档、材料阻断、巡检状态。
- 归档包改成时间线 + 档案盒视图。
- 签名链、留存策略、目录字段进入详情抽屉。
- 移动端采用手风琴分组：档案包、巡检、签名链、动态。

### 10. `/findings`

问题：

- 默认显示“加载失败”，这是 P0。
- 指标卡显示 `-`，用户无法判断系统是否有数据。
- 错误块占据主要区域，缺少恢复操作。

精修方案：

- 增加静态 fallback 疑点数据，至少展示 5 条样例。
- 错误态提供 `重试`、`查看规则库`、`进入医保审计`。
- 用空状态替代大红失败块：`当前未连接疑点服务，已展示样例清单`。

### 11. `/fund-compliance`

问题：

- 页面可读性尚可，但仍像后台模块聚合页。
- 缺少专题页面应有的“官方专题感”和业务叙事。
- 状态标签较多，主行动不突出。

精修方案：

- 首屏改为专题封面式：医保基金使用合规、审计范围、资料状态、主入口。
- 增加医保票据/基金流向线性插图。
- 只保留一个主 CTA：`进入审计工作台`。
- 次级内容折叠为“规则依据 / 费用表单 / 证据链”三块。

### 12. `/fund-compliance/review`

问题：

- 移动端 tab 高度约 33px，不足。
- tab `费用表单` 自动化未命中，可能是隐藏状态、可访问名称或按钮结构不稳定。
- 页面与 `/medical-audit` 的职责边界不够清楚。

精修方案：

- tab 改为标准 segmented control，hit area 44px。
- 保证每个 tab role、aria-selected、aria-controls 完整。
- 明确页面定位：这是专题审计页，不是全量医保审计控制台。

### 13. `/graph`

问题：

- 名为“知识图谱”，但当前更像列表/筛选页，缺少图谱视觉。
- 点击筛选后文字变化不明显。

精修方案：

- 首屏加入轻量节点链路图：项目、文档、规则、疑点、整改。
- 列表作为右侧详情或下方补充。
- 筛选切换时突出被选节点和关联线。

### 14. `/guided-check`

问题：

- 桌面 text density 8.41，移动高度约 5486px。
- 42 个链接，信息架构过重。
- “引导自查”应是向导流程，但当前像多个卡片堆叠。

精修方案：

- 改为 4 步向导：选择场景、确认资料、回答问题、生成建议。
- 每步只展示当前必需字段。
- 历史/参考资料放右侧辅助栏或折叠区。

### 15. `/knowledge-base`

问题：

- 多个 `查看` 按钮重复，自动化和用户都难区分。
- 页面仍偏数据面板，没有知识库治理的官方质感。
- 知识库总数和生产数据真实性容易被质疑，需要清晰标注来源。

精修方案：

- `查看` 改为 `查看法规政策`、`查看监管两库`、`查看医保目录`。
- 顶部增加知识库地图：系统库、公开库、个人库、项目库。
- 统计卡增加 `更新时间` 和 `数据来源`。

### 16. `/knowledge-query`

问题：

- `/api/v1/query` 返回 500。
- 空查询也进入请求流程，交互不够稳。
- 9 个字段/输入导致查询页看起来像后台筛选表单。

精修方案：

- 空查询直接前端校验：`请输入审计问题`。
- API 失败保留最近一次结果或样例结果，不让页面空掉。
- 精简为一行主问题 + 来源芯片 + 高级筛选折叠。
- 查询结果卡必须显示引用来源、可打开原文、可信等级。

### 17. `/medical-audit`

问题：

- 60 个按钮、13 个字段，是全站控制密度最高页面。
- 桌面表格右侧内容视觉拥挤，移动端转为超长卡片。
- 左侧规则导航、顶部 tab、指标卡、筛选、表格同时出现，首屏负担过重。
- 主任务不清晰：用户不知道是先看疑点、选规则、处理单据还是生成表单。

精修方案：

- 拆为 3 个清晰区块：
  - 左：规则/维度导航。
  - 中：疑点清单。
  - 右：选中单据详情。
- 首屏只展示一个默认任务：`待初审疑点`。
- 批量导入、导出、确认违规等危险/低频操作收进工具栏更多菜单。
- 移动端用单据列表 + 底部详情 sheet，不展示完整表格。

### 18. `/projects`

问题：

- 页面不重，但像通用项目管理模板。
- 缺少审计项目生命周期视觉。
- 选择项目后变化不明显。

精修方案：

- 改为项目阶段图：立项、资料、审查、复核、归档。
- 当前项目卡加入负责人、截止时间、待办风险。
- 切换项目时右侧详情明显更新，并保留选中态。

### 19. `/remediation`

问题：

- 高密度页面，移动高度约 4833px。
- 整改、补证、关闭门禁、动态全部平铺。
- 更像内控台账，不像用户可执行任务。

精修方案：

- 改为整改看板：待补证、待复核、待关闭、已完成。
- 每个整改项只显示事项、责任方、截止时间、风险等级。
- 证据请求和关闭门禁进入详情抽屉。

### 20. `/reports`

问题：

- 9 个字段，底稿生成流程偏表单化。
- 未选择会话时点击生成，反馈不明显。
- 缺少报告模板和生成过程状态。

精修方案：

- 改为三步：选项目、选材料、生成底稿。
- 未选择时在按钮附近显示 inline validation。
- 增加报告模板卡：审计底稿、问题清单、整改通知、归档摘要。
- 生成后显示预览卡和下载/继续编辑入口。

### 21. `/rules`

问题：

- 高密度页面，桌面 text density 8.90，移动高度约 4485px。
- 规则清单、最近运行、来源覆盖、发布门禁全部展开。
- `查看`、`审证`重复操作，缺少上下文。

精修方案：

- 首屏聚焦“规则健康度”和“待处理规则”。
- 规则详情进抽屉：规则来源、命中逻辑、最近运行、发布门禁。
- 按钮命名上下文化：`查看规则`、`审证规则`、`查看来源`。
- 移动端默认只展示规则摘要列表。

1. 先修 P0：`/findings` 和 `/knowledge-query`，保证核心页面不失败。
