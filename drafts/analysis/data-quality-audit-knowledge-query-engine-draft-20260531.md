# 知识库查询引擎 data 资料质量审计报告

## 1. 审计范围

本次审计对象为项目根目录下的 `data/`，采用只读扫描方式，不移动、不重命名、不删除任何源文件。

审计目标：

- 判断哪些资料可进入首版知识库索引
- 判断哪些资料应进入待处理队列
- 识别重复文件、系统垃圾文件、压缩包和抽取高风险文件
- 为后续知识库查询引擎工程实现提供初始数据边界

## 2. 总体结论

`data/` 当前适合作为知识库查询引擎的正式输入资产，但不适合无差别全量入库。

首版应直接处理：

- Markdown 法规文件
- txt 政策文件
- 可抽文本 PDF
- xlsx 规则和知识点表格

首版应进入待处理队列：

- png 图片资料
- zip / rar 压缩包

首版应忽略：

- `.DS_Store`

## 8. xlsx 规则表质量

当前共有 20 个 xlsx 文件，总行数约 17432 行。

明确重复：

- `智能监管“两库”规则和知识点/第一批/094ff52865424b4a9419bc78a3400e07.xlsx`
- `智能监管“两库”规则和知识点/第一批/094ff52865424b4a9419bc78a3400e07 (1).xlsx`

高风险表格：

- `第一批/8b99adab657f4beb9d6494fb42e7eda8.xlsx`
  - sheet `"药品儿童专用“规则对应知识药品代码`
  - 4374 行，16384 列
- `第九批/6aa58f9f4c1241daa5befc1a9837fe42.xlsx`
  - sheet `"药品限二线使用“知识点对应药品代码`
  - 605 行，16384 列

判断：这两个 sheet 的列数异常，可能存在格式污染、隐藏列或解析边界问题。首版抽取器必须限制有效列范围，不能按最大列数盲目切分。

## 9. 重复文件

哈希检查发现 3 组明确重复：

| 类型 | 重复文件 |
| --- | --- |
| Markdown | `人民检察院公益诉讼办案规则_20210629_转自DOC.md` 与 `人民检察院公益诉讼办案规则_20210629.md` |
| Markdown | `人民检察院刑事诉讼规则_20191230.md` 与 `人民检察院刑事诉讼规则_20191230_转自DOC.md` |
| xlsx | `094ff52865424b4a9419bc78a3400e07.xlsx` 与 `094ff52865424b4a9419bc78a3400e07 (1).xlsx` |

处理建议：

- 源文件保留不动
- 入库时以 `sha256` 去重
- 保留多个源路径到同一 canonical document 的映射
- 查询引用时优先展示非副本命名文件

## 10. Markdown 质量观察

Markdown 法规共 17184 个。

观察结果：

- 无空文件
- 只有约 735 个文件首行以 Markdown `#` 标题开头
- 约 5 个文件首行为空
- 多数法规文件标题来自正文首行或文件名，而不是标准 Markdown 标题

处理建议：

- 文档标题优先从正文首个非空行提取
- 若正文标题缺失，则回退到文件名解析
- 条款切分不能依赖 Markdown 标题，必须支持中文法规结构，如 `第一条`、`第二章`、`附则`

## 11. 命名与来源问题

当前资料保留了大量原始来源命名，不建议在项目初始化阶段批量重命名。

已观察到的命名问题：

- 文件名包含括号、空格、加号、下划线等混合符号
- 存在 `(1)` 副本
- 部分法规存在 `_转自DOC` 后缀
- 部分法规日期缺失，仅以 `_` 结尾

处理建议：

- 不批量改名
- 入库时新增规范化字段：`normalized_title`、`source_file_name`、`effective_date`、`source_variant`
- 保留原始路径作为审计追溯字段

## 12. 初始资料分层建议

### 12.1 第一优先级

- `医保目录`
- `智能监管“两库”规则和知识点` 中的 xlsx 和主 PDF
- `风险负面清单`
- `医疗保障法律法规及政策汇编.pdf`

理由：这些资料直接服务医保审核、规则解释和审计场景。

### 12.2 第二优先级

- `全量法律` 中文件名明确包含医保、医疗保障、基本医疗保险、医疗机构、药品、处方、门诊、住院、诊疗、卫生、生育保险、工伤保险等关键词的法规文件

当前仅按文件名筛选约 432 个候选文件。该数字只代表文件名候选，不代表最终内容相关清单。

### 12.3 第三优先级

- `全量法律` 中需要通过内容命中才能识别的医疗相关文件

理由：这些文件可能正文相关但文件名不显式相关，需要后续内容级扫描与评测。

## 13. 进入工程实现前的约束

知识库查询引擎首版实现必须满足：

- 文件扫描必须支持 `sha256` 去重
- 压缩包、图片、系统文件不能静默失败
- xlsx 抽取必须限制有效列，防止 16384 列异常污染 chunk
- PDF 抽取必须记录字符数和抽取质量状态
- Markdown 切分不能依赖 `#` 标题
- 所有 chunk 必须保留原始路径、资料包版本、索引版本和引用定位

## 14. 建议的下一步

进入工程实现前，先做两个最小准备动作：

1. 定义 `data` 文件入库分类规则。
2. 用 `data/医保审核前期资料/` 生成首个 `source_package_version`。

随后再进入实施计划中的 Task 1 到 Task 4：

- 数据源盘点与资料包版本化
