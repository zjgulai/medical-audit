# 医疗审计 MVP 范围基线

## 1. 统一结论

基于当前仓库材料，项目应被统一理解为：

- 一个面向公立医院场景的私有化 AI 智能审计管理系统
- 第一阶段先落地单院定制 MVP
- 业务切口先收敛到 HIS 数据驱动的医疗/医保合规审计
- 核心能力不是单点模型，而是“知识支撑 + 风险识别 + 审计交付”的业务闭环
- 前端产品形态调整为参考系统式 AI 审计门户，包含左侧 9 模块导航、顶部多标签、提示词型智能体、知识库、文档检索、AI 数据分析、知识图谱、底稿报告和项目管理。

当前 V1.0 PRD 已落地为 `docs/product/product-prd-medical-audit-v1-stable.md`。本文件继续作为范围裁剪基线，PRD 负责承接角色、流程、功能需求、验收标准和后续执行计划。

## 2. 产品属性判定

### 2.1 业务属性

- `B2B/B2G` 混合属性的企业级项目型产品
- 强行业知识依赖，强合规属性，强本地化部署约束
- 不是开放式通用 AI 工具，而是面向审计岗位的垂直工作系统。
- 首期智能体是“一个智能体对应一个提示词”的提示词型助手，不是复杂多步 agent 编排。

### 2.2 交付属性

- 单院定制优先
- 私有化部署优先
- 离线更新能力是首版必须预留的能力，不是后补能力

### 2.3 数据属性

- 第一阶段只接 HIS
- 当前资料明确排除了 LIS、PACS、财务系统在 MVP 的接入
- 训练、验证和联调都依赖院方 DDL、脱敏历史数据和报告模板

## 3. 当前 MVP 边界

### 3.1 应纳入 MVP

- 法规库、知识库、地方特色库等“两库一特色库”能力
- 法规/知识检索问答与基础合规判断
- 参考系统式 AI 审计门户和多标签工作区
- 提示词型审计智能体，可新增智能体
- 上传表格 AI 数据分析能力和审计数据分析入口
- 项目列表和项目成员管理
- 个人知识库、系统知识库、公开知识库的首期只读展示
- HIS 数据抽取、清洗、落库
- 0/1 合规风险识别
- 审计底稿与报告输出
- 本地部署、权限、审计日志和离线更新基础能力

### 3.2 暂不纳入 MVP

- LIS / PACS / 财务系统接入
- 风险等级精细分层
- 多院多租户产品化能力
- 移动端
- 跨行业通用审计专题交付；财政、农业、国企、采购等专题当前只作为 UI 参考
- 复杂多轮智能体编排
- 完整组织级权限、邀请、审批和项目成员真实权限生效
- 通用 BI 平台、大文件高并发表格分析和生产级数据分析沙箱

## 4. 核心用户与关键角色

- 一线审计员：发起查询、执行分析、生成底稿和报告
- 审计科主任/负责人：审核结果、签字验收、跟踪整改
- 医院信息科：提供 DDL、联调环境、脱敏测试数据
- 业务专家/审计专家：确认规则、标注口径、报告模板

## 5. 当前最可信的业务主链路

1. 导入法规、知识、负面清单和医保目录等知识资产
2. 接入 HIS 表结构与样例数据，建立审计数据底座
3. 根据规则与模型完成合规识别
4. 输出问题明细、证据、底稿和审计报告
5. 进入整改跟踪

## 6. 范围冲突与取舍

当前材料存在三个层级：

- `AI医疗审计系统项目计划.docx` 提供的是较早、较大范围的方案
- `AI智能审计管理系统 V1.0 开发计划` 已经收敛到 HIS、单院 MVP 和已确认的门户化前端
- `会议达成共识` 进一步明确了只做 0/1 合规判定、只接 HIS、不拆功能阶段

当前项目应以后两者为准。门户化 UI 可以参考外部系统的信息架构，但不能把跨行业“大而全平台描述”直接写入首版交付范围。

## 7. 中长期外延判断

从脑图材料和会议待办可以看出，项目中长期目标很可能会走向“两库四审”：

- 两库：法规/知识等知识支撑体系
- 四审：医保使用合规、医疗诊疗合规、采购合规、工程审计合规等专题能力

这个方向可以作为路线图参考，但不能直接写进首版 PRD 的交付范围。

## 8. PRD 后仍需确认的问题

V1.0 PRD 已经给出当前执行基线，但以下事项仍属于外部依赖或院方确认项：

- 目标客户首批到底由医院内审部门主导，还是医保协同项目共同主导。
- 首个细分场景究竟落在诊疗合规、收费合规、医保基金使用，还是参保人员审计。
- 风险规则库由谁维护，更新频率和责任边界如何定义。
- 报告验收以什么模板、什么签字流程为准。
- `92%` 准确率的口径，到底按条目、按问题、按病例还是按案件计算。

## 9. AI 审计门户 UI/UX 首版范围

前端首版界面调整为 `AI智能审计管理系统` 门户，对话入口仍是高频入口，但产品不做开放式闲聊平台。

应纳入首版 UI：

- 全局门户壳：左侧 9 模块导航、顶部栏、顶部多标签、历史对话区。
- AI 对话：自然语言对话、引用型回答、证据质量状态、附件入口、智能体选择、最近对话。
- 我的智能体：提示词型智能体列表、新增智能体、分类筛选。
- 智能体广场：医疗/医保审计模板展示、搜索、分类和分页。
- 知识库：个人、系统、公开知识库三类只读展示。
- 文档检索：搜索框、搜索历史、库分类统计、对话文档、知识库文档、原文预览入口。
- AI 数据分析：上传 `.xlsx` 或 `.csv` 表格并返回字段概览、质量提示和初步审计分析；同时展示审计数据分析入口。
- 知识图谱：项目图谱列表或静态关系预览。
- 审计底稿/报告：历史生成记录、底稿生成入口、报告签发和整改导出入口。
- 项目管理：项目列表、成员列表、角色展示、新增成员入口。
- 审计日志与索引管理：保留管理员/运维入口，但减少普通业务页中的工程术语。

暂不纳入首版 UI：

- 服务端持久化多轮会话编排。
- 复杂 agent 工具编排和自主办案流程。
- 跨行业专题能力交付。
- 完整权限系统、成员邀请审批和成员权限真实生效。
- 生产级通用 BI 平台。
- 面向院方汇报的 Figma 高保真稿。

实现约束：

- 后端状态必须显性展示；不得在检索未加载时伪装成可查询状态。
- 所有引用答案必须保留原文预览入口。
- 对话结果必须拆成结论、证据、质量状态和可点击原文，不把长证据堆进单一气泡。
- 上传表格分析的输出必须标注证据等级和数据来源，不能把模型输出直接写成审计结论。
- 所有新增导航入口必须有真实页面，不得再以低信息量 `plan` 或纯桥接空态替代。
