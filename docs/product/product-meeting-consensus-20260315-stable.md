# 医疗审计项目会议共识

## 一、会议达成共识

1. **产品定位与范围**
- MVP定义：1个月内跑通1个细分场景，后续逐步迭代新增财务审计、药品审计等模块，第一阶段聚焦核心不贪多
- 功能范围：`a.知识库/法规问答+合规判断` + `b.风险分析+底稿报告输出` 两个核心功能同步开发，不拆分阶段
- 数据范围：第一阶段仅接入HIS系统数据，暂不考虑LIS/PACS/其他财务系统数据；HIS仅抽取原始数据，不做跨部门合表，只输出自身审计结果
- 风险判定规则：第一阶段先做非黑即白的0/1合规判定，暂不考虑风险等级划分

2. **数据与技术相关**
- 数据量级：目标医院日均药品行数据保底按10万+估算，取1年历史数据用于模型训练测试；合规标签统一用项目规则重新打标，再和医院历史标注做准确率比对
- 对接方案：前期开发仅需要HIS表结构的DDL（数据定义语言），开发侧用虚拟数据完成测试；后续对接用医院提供的脱敏老测试数据即可

3. **项目管理**
- 协作平台：统一用钉钉搭建项目空间，同步进度、传输大文件
- 预算管控：提前对齐MVP开发人天，若人天偏差超出预期及时调整，避免无效投入；开发需兼顾后续模块扩展，做好兼容设计
